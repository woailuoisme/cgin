# 通用基础规则 (General Rules)

本规则定义了跨项目通用环境约束、交互通信规范与工程实施纪律。

---

## 1. 宿主环境与终端纪律 (Environment & CLI Discipline)

1. **宿主与 Shell 规范**：macOS / Linux 环境，默认 Shell 为 `zsh`/`bash`，文本换行符统一使用 `LF`。
2. **命令代理与 Token 节约**：终端 Shell 命令必须优先使用 `rtk` 前缀（如 `rtk git status`、`rtk cargo test`），利用输出压缩降低上下文消耗。
3. **严禁 `cd` 切换目录**：绝对严禁在终端命令中使用 `cd` 改变工作目录。所有命令必须通过工具参数（如 `-C`、`--dir` 或指定相对/绝对路径）保持在工作区根目录执行。

## 2. 沟通交互与语义规范 (Communication & Semantics)

1. **默认简体中文**：所有交互分析、架构设计、代码解释、文档编写与任务总结默认统一使用清晰地道的简体中文。
2. **直奔主题**：省略冗长客套、礼节性寒暄与机械复述，保持高信息密度与专业技术表达。
3. **可点击链接规范**：提及文件路径或代码符号时，必须使用标准可点击的 Markdown 链接（如 `[filename](file:///path/to/file)` 或 `[Symbol](file:///path/to/file#L10-L25)`）。
4. **Git 提交契约**：Commit 消息严格遵循 Conventional Commits 规范（如 `feat:`, `fix:`, `refactor:`, `test:`, `chore:`）。

## 3. 工程实施与质量闭环 (Engineering Discipline & Quality Gates)

1. **主动对齐与消除假设**：遇到需求模糊、缺少上下文或存在多种技术实现方案时，必须先列出利弊权衡并主动向用户确认，严禁盲目假设。
2. **外科手术式最小变更**：最小化改动范围，仅修改与目标任务直接相关的代码。严禁随意变动无关文件、格式排版或既有注释。
3. **闭环验证与质量门禁**：任何代码或配置变更完成后，必须主动按序运行当前工作区的格式化工具、静态检查（Linter）与自动化测试，确保 0 报错并完全通过后方可宣布交付。
